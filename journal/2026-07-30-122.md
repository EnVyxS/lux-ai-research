## 4. Sebab pertama, terukur dari kode: **tanda tangan `silang_funding` disalahbaca**

`lux_ai/serapan/silang_funding.py` (blob **`42c3aa9dc2c16220b79cf9c9e46979dd000fd393`**,
dibaca UTUH) menyatakan tiga hal yang membatalkan rancangan V1:

1. `lubang_funding(funding) -> Tuple[Set[Kunci], Dict[str, Any]]` —
   mengembalikan **pasangan** (himpunan, meta), bukan peta `simbol -> daftar bulan`.
   `bentangan_kohort` V1 menulis `lubang = silang_funding.lubang_funding(...)` lalu
   `lubang.get(simbol, [])` di dalam `ringkas_simbol`. **`tuple` tidak punya
   `.get`** → `AttributeError` pada anggota kohort pertama.
2. `baca_medan_baris(...) -> Tuple[Dict[Kunci, Any], Dict[str, Any]]` — juga
   pasangan. V1 menyimpannya sebagai `lilin` lalu memanggil `lilin.get(...)`.
   Cacat kedua yang bentuknya sama.
3. **Kunci laporan kehidupan adalah `Kunci = Tuple[str, str]`**, yakni
   `(simbol, bulan)` — **bukan** string gabungan. Maka `POLA_KUNCI` dan
   `pisah_kunci` salah sasaran sejak lahir: docstring V1 berbangga "format kunci
   TIDAK diasumsikan", padahal ia mengasumsikan hal yang lebih dalam — bahwa
   kuncinya berupa **string**. `str(("BTCUSDT", "2026-06"))` berakhir dengan `)`,
   sehingga regexnya menolak SELURUH 19.586 kunci; seandainya `AttributeError`
   tidak lebih dulu terjadi, `cacah_kunci_gagal_pisah` akan bernilai 19.586 dan
   `kode_keluar` 2. Lookup `byte_parquet.get(f"{simbol}{b}")` gagal karena sebab
   yang sama.

Jadi V1 mustahil menghasilkan laporan. Aturan 71 ditaati **sebagiannya saja**:
nama fungsi dikutip dari kode, tetapi **bentuk kembaliannya tidak dibaca**.

## 5. Sebab kedua: run yang gagal tidak meninggalkan jejak apa pun

Langkah commit `bentangan_kohort.yml` (dan `anatomi_tengah.yml`) berbunyi:

```
git add -f reports/bentangan_kohort.json reports/bentangan_kohort.log reports/bentangan_kohort_status.json || true
git commit -m "…" || exit 0
```

`git add` dengan satu pathspec yang tidak ada **membatalkan seluruh penambahan**,
bukan hanya berkas yang hilang. `|| true` menelan galatnya; `git commit` lalu tidak
menemukan apa pun untuk dicommit dan `|| exit 0` menutup langkahnya dengan tenang.
Akibatnya **log yang sudah ditulis `tee` pun ikut lenyap**, dan dari luar run yang
gagal tampak persis seperti run yang tidak pernah menyala. Ini berlawanan dengan
perilaku `ci.yml` yang menulis laporan LEBIH DULU lalu baru `exit ${kode}` (aturan
72), dan ia menyembunyikan tepat kelas kegagalan yang paling perlu terlihat.
